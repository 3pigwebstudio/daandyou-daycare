# 강서 다앤유 재활 데이케어센터 — v1.8 95점 완성도 설계

## 0. 문서 상태

- 단계: 설계 확정 전 초안
- 기준 구현: v1.7 Astro 정적 사이트
- 디자인 결정: 대표가 현재 시안의 시각 방향에 만족함
- 사진 결정: 제공 사진을 우선 적용하되, 실제 센터 사진 확보 후 같은 영역에서 교체함
- 목표: 승인된 인상을 유지하면서 신뢰, 전환, 반응형 일관성, 접근성, 검색·공유 품질을 보강해 내부 평가 95점 이상 달성

## 1. 변경하지 않는 것

- Calm Editorial Healthcare 방향
- 공식 다앤유 로고와 핵심 색상 `#206E88`, `#193249`, `#D8EAF3`
- 데스크톱의 대형 Hero와 긴 스크롤 서사
- 모바일 홈의 3개 진입 메뉴: 소개 / 프로그램 / 이용 안내
- 과장된 의료 효과, 검증되지 않은 수치, 가공 후기 미사용
- 상담 전환의 최우선 행동은 전화 연결

이번 단계는 전면 리디자인이 아니다. 승인된 시안에 정보와 증거를 보강하고, 모바일과 데스크톱이 같은 브랜드와 핵심 내용을 전달하도록 정리하는 작업이다.

## 3. 핵심 사용자 흐름

보호자가 홈페이지에서 해결해야 할 질문을 네 단계로 정리한다.

1. **믿을 수 있는 곳인가?** — 운영 철학, 전문인력, 실제 공간과 활동 사진
2. **우리 부모님에게 맞는가?** — 식이·연하, 움직임·균형, 인지·일상 프로그램
3. **실제로 이용할 수 있는가?** — 대상, 운영시간, 위치, 송영, 상담 절차
4. **다음에는 무엇을 하면 되는가?** — 전화 상담 및 확인할 정보 안내

각 섹션은 새로운 답을 하나씩 제공해야 하며, 같은 홍보 문구를 반복하지 않는다.

## 4. 반응형 콘텐츠 원칙

모바일과 데스크톱은 표현 방식은 달라도 핵심 정보는 동일해야 한다.

| 핵심 내용 | 모바일 | 데스크톱 |
|---|---|---|
| 브랜드 약속 | 3개 메뉴 위 짧은 문장 | 이미지 중심 Editorial Hero |
| 신뢰 근거 | 소개 상세의 3개 팩트 | Hero 다음 신뢰 스트립 + 전문인력 섹션 |
| 프로그램 | 스와이프 카드 4개 | 우선순위를 반영한 제한적 Bento 구성 |
| 하루 경험 | 프로그램 뒤 4개 순간 요약 | 4단계 타임라인 |
| 이용 정보 | 이용 상세 + FAQ | 이용 패널 + FAQ |
| 상담 | 하단 고정 1탭 | 헤더, 이용 섹션, 최종 CTA |

- 전환 기준은 현재와 같이 `850px`을 사용하되, 768–1024px 구간을 별도 검증한다.
- 모바일과 데스크톱에서 센터명, 핵심 약속, 프로그램 명칭, 이용 안내 문구가 서로 다르게 변질되지 않게 공통 데이터에서 출력한다.
- 모바일 홈은 승인된 3개 카드 구조를 유지한다. 상세 화면에서 핵심 콘텐츠가 누락되지 않도록 보강한다.

## 5. 화면 설계

### 5.1 공통 헤더

- 공식 로고는 로컬 파일을 우선 사용하고 외부 CDN은 보조 수단으로 둔다.
- 데스크톱: 소개 / 프로그램 / 이용 안내 / 상담 CTA.
- 모바일: 로고 + 현재 상세 화면에서만 명확한 뒤로 가기. 브랜드 로고 탭은 홈 복귀.
- 스크롤 상태에서도 대비와 높이가 유지되어야 한다.

### 5.2 Hero

- 현재 문구 `편안한 하루에, 재활의 전문성을 더하다.`를 유지한다.
- 제공 사진은 인물 얼굴 위에 텍스트가 겹치지 않도록 안전 영역을 지정한다.
- 이미지 하단에는 `제공 이미지` 또는 `콘셉트 이미지` 상태를 데이터에 따라 표시한다.
- CTA는 `이용 상담하기`로 통일하고, 보조 링크는 `전문 프로그램 보기`로 둔다.

### 5.3 신뢰 근거

- 장기요양 현장 경험 / 작업치료 전문성 / 전문자문 네트워크를 하나의 신뢰 스트립으로 유지한다.
- 확인되지 않은 경력 연수, 치료 효과, 이용자 수는 추가하지 않는다.
- 전문인력의 이름·직무·전문영역은 최종 공개 동의 후 표시한다.

### 5.4 프로그램 Bento

데스크톱에서만 제한적으로 사용한다.

- 큰 카드: 다앤유가 재활 관점으로 하루를 설계한다는 핵심 설명
- 중간 카드: 식이·연하 지원
- 중간 카드: LSVT BIG 기반 움직임
- 작은 카드: 인지·일상 활동
- 작은 카드: 함께하는 하루

카드 하나에는 제목, 한 문장 설명, 하나의 이미지 또는 그래픽만 둔다. 모바일은 현재 스와이프 카드를 유지하되 본문을 17px 중심으로 확대하고 `이전`, `다음` 텍스트 버튼을 제공한다.

### 5.5 이용 안내와 FAQ

- 센터 위치, 운영시간, 이용 전 상담, 송영 여부를 명확히 분리한다.
- 값이 미확정이면 `준비 중`으로 표시하며 임의의 정보를 넣지 않는다.
- FAQ 기본 항목:
  1. 이용 대상은 어떻게 확인하나요?
  2. 어떤 프로그램에 참여할 수 있나요?
  3. 송영 가능 지역은 어디인가요?
  4. 운영시간과 이용 절차는 어떻게 되나요?
  5. 상담 전 무엇을 준비하면 되나요?

### 5.6 최종 CTA

- 문구: `우리 부모님께 맞는 하루인지 먼저 이야기해 보세요.`
- 버튼: `이용 상담하기`
- 센터 전용번호가 확정되기 전에는 기존 대표번호임을 버튼 가까이에 명시한다.
- 카카오·문의폼은 실제 운영 채널이 확정될 때만 추가한다.

## 6. 사진 교체 계약

사진은 레이아웃과 분리된 콘텐츠 자산으로 관리한다. 추후 실제 사진을 넣을 때 컴포넌트와 CSS를 다시 설계하지 않는다.

| 슬롯 | 권장 비율 | 최소 크기 | 현재 | 최종 교체 기준 |
|---|---:|---:|---|---|
| Hero 공간·돌봄 | 16:9 | 1920×1080 | 제공/콘셉트 사진 | 밝은 공용 공간, 자연스러운 상호작용, 텍스트 안전 영역 확보 |
| 식사 지원 | 4:3 | 1200×900 | 콘셉트 사진 | 실제 식사 지원 장면, 개인정보·동의 확인 |
| 움직임 활동 | 4:3 | 1200×900 | 콘셉트 사진 | 실제 활동 장면, 안전 장비와 자세가 자연스럽게 보임 |
| 센터 생활 | 4:3 | 1200×900 | 콘셉트 사진 | 실제 공간과 일상 활동을 함께 보여 줌 |
| 전문인력 | 1:1 또는 4:5 | 800×800 | 미정 | 공개 동의된 인물만 사용 |

- 파일 형식은 WebP 우선, 필요 시 AVIF 병행.
- 얼굴·명찰·문서·건강정보가 포함된 사진은 공개 동의와 비식별 여부를 확인한다.
- `alt`는 사진의 장면과 정보 목적을 설명하고 `좋은`, `최고` 같은 평가 표현을 넣지 않는다.
- 사진 상태를 `concept`, `provided`, `final`로 관리해 캡션을 자동 전환한다.

## 7. 타이포·접근성 기준

- 모바일 본문: 원칙적으로 17px, 보조문구 최소 13px.
- 데스크톱 본문: 17–19px.
- 주요 터치 대상: 최소 48×48px, 핵심 CTA 높이 56px 이상.
- 텍스트 대비 WCAG AA 목표.
- 프로그램 이전·다음은 아이콘 단독이 아니라 한글 레이블을 제공한다.
- 200% 확대에서 콘텐츠 손실, 겹침, 가로 스크롤이 없어야 한다.
- `prefers-reduced-motion`에서 진입 모션과 스크롤 모션을 제거한다.
- 320, 360, 390, 768, 850, 851, 1024, 1440px을 검증한다.

## 8. 검색·공유 설계

- canonical URL을 실제 운영 도메인으로 설정한다.
- OG 제목·설명·이미지 및 Twitter Card를 추가한다.
- 센터 공식 정보 확정 후 Organization/LocalBusiness 계열 구조화 데이터를 적용한다.
- `sitemap.xml`, `robots.txt`, 파비콘·앱 아이콘을 제공한다.
- 각 메타데이터는 임시 주소·임시 전화번호를 영구 정보처럼 표시하지 않는다.

## 9. 구현 순서

### Phase A — 디자인 일관성

1. 모바일·데스크톱 공통 콘텐츠 데이터 정리
2. 모바일 타이포와 조작 영역 확대
3. CTA 명칭과 상태 문구 통일
4. 프로그램 Bento 및 모바일 상세 콘텐츠 보강

### Phase B — 신뢰와 사진

1. 사진 슬롯과 상태 데이터 구현
2. 제공 사진 1차 적용
3. 인력·프로그램·이용 정보의 공개 가능 여부 확인
4. 실제 사진 도착 시 같은 파일 슬롯에 교체

### Phase C — 검색·검수

1. OG, canonical, sitemap, 구조화 데이터
2. 200% 확대, 키보드, 실기기 전화 연결
3. iOS Safari / Android Chrome / 데스크톱 브라우저 확인
4. 대표 최종 확인과 변경 이력 기록

## 10. 완료 조건

- 대표 만족 상태를 유지하면서 핵심 화면의 시각적 인상이 급격히 달라지지 않음
- 모바일과 데스크톱에서 동일한 핵심 정보와 CTA 제공
- 임시 사진과 실제 사진의 상태가 명확히 구분됨
- 미확정 운영정보를 사실처럼 노출하지 않음
- 내부 평가표 95점 이상
- Astro 검사와 빌드 오류 0건
- 공개 배포 후 HTML·이미지 응답 정상, 브라우저 오류 0건
- 대표 최종 확인 및 사진 교체 대기 항목을 문서에 기록

## 11. 외부 확정이 필요한 항목

- 강서 센터 전용 전화번호
- 정확한 주소와 지도 위치
- 운영시간과 송영 범위
- 전문인력 이름·직무·사진 공개 동의
- 프로그램 제공 범위의 최종 문구
- 실제 센터 사진과 인물 사진의 웹 공개 동의
- 운영 도메인
