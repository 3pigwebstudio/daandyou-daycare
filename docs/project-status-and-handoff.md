## 3. 현재까지 완료된 결과

### 브랜드와 메시지

- 정식 업체명을 `다앤유 재활 데이케어센터`로 통일했다.
- 정식 명칭이 아닌 `강서센터`를 업체명의 보조 표기로 사용하지 않는다.
- 헤더에서 업체명을 모바일·데스크탑 공통으로 즉시 인지할 수 있게 했다.
- 핵심 문구를 `재활의 전문성을 일상의 돌봄으로`로 확정했다.
- 대표가 현재 디자인 방향에 만족한 상태다.

### 데스크탑

- 1980×1080을 대표 화면으로 하는 4열 편집형 Hero를 구현했다.
- 1열은 카드 없이 메시지·설명·상담 CTA를 배치했다.
- 중앙 2열은 일상 돌봄과 재활 전문성을 보여주는 대표 사진 두 장으로 구성했다.
- 사진 A는 32px 곡률의 계단형 절개 프레임, 사진 B는 30px 곡률의 세로형 프레임을 사용한다.
- 사진 A와 B의 하단 기준선을 맞추고 내부 비율을 `1.14fr : 0.86fr`로 구성했다.
- 역할이 불명확했던 `01·02·03` 전문성 배지와 사진 분류 배지를 제거했다.
- 오른쪽에는 스마트폰의 큰 버튼처럼 인식되는 퀵 메뉴 3개를 유지했다.

### 모바일

- 50대 보호자에게 안정적인 16:9 풀폭 카드 3개를 적용했다.
- `보기` 배지, 글래스 효과, 외곽 비대칭 장식을 제거했다.
- 청록·네이비·스카이 브랜드 색상은 유지했다.
- 소개, 프로그램, 이용 안내를 앱처럼 이동할 수 있는 상세 화면으로 구성했다.
- 하단 고정 전화 상담 CTA와 48px 이상의 주요 조작 영역을 적용했다.

### 콘텐츠와 기능

- 다앤유 소개, 전문인력, 프로그램, 하루 구성, 이용 안내, FAQ, 상담 CTA를 구현했다.
- 프로그램은 식이·연하, LSVT BIG 기반 움직임, 인지·일상, 함께하는 하루로 구성했다.
- 임시 사진과 최종 사진을 구분할 수 있도록 `concept / provided / final` 상태를 데이터화했다.
- 전화 연결, 지도 자리표시자, FAQ 펼침, 모바일 프로그램 슬라이더를 구현했다.
- 연락처·주소·운영시간·프로그램·FAQ는 `src/data/site.ts`에서 관리한다.

### 기술과 배포

- Astro 정적 빌드와 Cloudflare Workers Static Assets 배포를 구성했다.
- Astro 검사 결과 0 errors, 0 warnings, 0 hints를 확인했다.
- 1980, 1440, 1024, 1023, 851, 430, 390, 360px 반응형 구성을 점검했다.
- 대표 점검 폭에서 가로 스크롤과 브라우저 콘솔 오류가 없음을 확인했다.
- canonical, Open Graph, Twitter Card, robots.txt, sitemap.xml, Organization JSON-LD를 구현했다.

## 4. 확정된 디자인 원칙

1. 업체명은 항상 `다앤유 재활 데이케어센터`를 사용한다.
2. `강서센터`는 정식 업체명 또는 보조 브랜드명으로 사용하지 않는다.
3. 모바일은 대칭·풀폭·명확한 조작성을 우선한다.
4. 글래스모피즘은 모바일 핵심 카드에 사용하지 않는다.
5. 장식 배지는 정보 역할이 있을 때만 사용한다.
6. 데스크탑의 비대칭은 중앙 사진 구도 안에서만 제한적으로 사용한다.
7. 50대 이상 보호자가 3초 안에 업체명과 주요 메뉴를 이해할 수 있어야 한다.
8. 실제 운영 범위가 확정되지 않은 내용을 홍보 문구로 단정하지 않는다.
9. 콘셉트 사진은 실제 센터 사진처럼 표현하지 않는다.
10. CTA의 기본 명칭은 `이용 상담하기`로 통일한다.

## 5. 다시 적용하지 않을 디자인

아래 항목은 검토 후 폐기했으므로 특별한 재승인 없이 되돌리지 않는다.

- 모바일 카드의 과도한 비대칭 회전과 겹치는 외곽선
- 모바일 카드의 글래스 프레임
- 카드 우측 상단의 `보기` 배지
- 역할이 불분명한 중앙 `01·02·03` 전문성 배지
- 사진 상단의 `식사·관계·일상`, `재활 활동·움직임` 분류 배지
- 업체명 아래에 `강서센터`를 지점명처럼 표기하는 방식
- 1980×1080 화면에서 콘텐츠 폭을 지나치게 좁게 제한하는 구성

## 7. 재사용 방법

이 저장소를 다른 지점 또는 유사한 데이케어센터 프로젝트에 재사용할 때 다음 순서로 작업한다.

1. 저장소를 복제하고 새 프로젝트명과 배포 대상을 확정한다.
2. `src/data/site.ts`에서 업체명, 설명, 전화, 주소, 운영시간을 교체한다.
3. `public/images/`의 사진을 사용 허가가 확인된 실제 사진으로 교체한다.
4. 사진 상태를 `final`로 변경하고 대체 텍스트를 실제 장면에 맞게 수정한다.
5. 프로그램과 FAQ를 실제 제공 범위에 맞게 검수한다.
6. `BaseLayout.astro`의 LocalBusiness 구조화 데이터와 최종 도메인을 적용한다.
7. `robots.txt`, `sitemap.xml`, OG 이미지와 canonical을 새 도메인으로 교체한다.
8. 브랜드 색상과 로고만 바꿀 때도 모바일 대비와 48px 터치 기준을 유지한다.
9. `npm run check`, `npm run build`, 반응형·실기기 검수를 완료한다.
10. Cloudflare에 배포하고 검색엔진 등록을 진행한다.

## 9. 완료 판정 기준

다음 조건이 모두 충족되면 제작 완료율을 100%로 판정한다.

- 공식 주소·전화·운영시간·프로그램이 고객 승인 상태다.
- 모든 콘셉트 사진이 승인된 최종 사진으로 교체됐다.
- 최종 도메인과 LocalBusiness 구조화 데이터가 적용됐다.
- 실제 iOS·Android·1980×1080 모니터 검수가 끝났다.
- 200% 확대, 키보드, 스크린리더 핵심 동선 검수가 끝났다.
- 전화 상담과 길찾기 링크가 실제 환경에서 정상 동작한다.
- 검색엔진 소유권 확인과 sitemap 제출이 완료됐다.
- 배포 후 치명적 오류와 미확정 안내 문구가 남아 있지 않다.
